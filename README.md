## Огляд

AI-генератор академічних робіт — Python-застосунок, що автоматизує створення структурованих академічних текстів через **мульти-агентний асинхронний пайплайн**. Система будує план роботи, паралельно збирає джерела з наукових баз (OpenAlex) та вебу (Tavily), генерує текст академічного стилю з коректними посиланнями та оформлює результат у DOCX за українськими стандартами (**ДСТУ 8302:2015**). Працює через веб-інтерфейс або CLI, підтримує **OpenAI та Gemini** з можливістю балансувати ціну й якість між моделями.

## Можливості

- **🤖 Мульти-агентний пайплайн** — асинхронна оркестрація етапів:
  - **Blueprint / Планувальник** — аналізує тему й зміст, класифікує розділи (теорія / практика / вступ / висновки), визначає сутності та підтеми для дослідження
  - **Дослідник (Research)** — паралельно збирає релевантні джерела: **OpenAlex** (наукові публікації) + **Tavily** (веб-пошук), з агрегацією та дедуплікацією
  - **Автор** — генерує текст кожного розділу з урахуванням зібраних джерел і контексту сусідніх розділів; вступ і висновки — окремим проходом

- **⚡ Паралельність** — розподіл тем і генерація body йдуть конкурентно (`asyncio`), що суттєво пришвидшує роботу над великими документами

- **🔌 Pluggable-провайдери** — абстрактний асинхронний інтерфейс (`BaseAIProvider`); реалізації **OpenAI** та **Gemini**, легко додати нового. Ретраї з експоненційним backoff (`tenacity`)

- **🎚️ Пресети якості** — `economy` / `standard` / `quality`: різні моделі для основної генерації та дешевий helper для службових кроків (план, переклад, вступ/висновки) — контроль вартості без втрати якості

- **📚 Оформлення за ДСТУ** — бібліографія за **ДСТУ 8302:2015** (розрізняє кириличні/латинські джерела, сортування, перенумерація), DOCX за академічними вимогами: A4, поля 3/1.5/2/2 см, Times New Roman 14pt, інтервал 1.5, вирівнювання по ширині, розділи з нової сторінки

- **🌐 Веб-інтерфейс** — панель на Flask: інтерактивний редактор змісту, логи генерації в реальному часі через **Server-Sent Events (SSE)**, керування моделлю/пресетом/темою, регенерація окремого розділу

- **💻 Режим CLI** — повноцінний запуск з аргументами для автоматизації

- **🧩 Pydantic-моделі** — типізований домен (джерела, секції, план); **Jinja**-шаблони промптів в одному місці (`core/prompts.py`)

## Архітектура

```
┌─────────────────────────────────────────────────────────┐
│                  Веб-інтерфейс / CLI                     │
│               (Flask + SSE  /  argparse)                 │
└──────────────────────┬──────────────────────────────────┘
                       │
              ┌────────▼─────────┐
              │   Orchestrator    │
              │   (асинхронний)   │
              └────────┬─────────┘
     план → розподіл тем → research → генерація body → вступ/висновки
          │              │              │
          ▼              ▼              ▼
   ┌────────────┐  ┌──────────────┐  ┌──────────────┐
   │ AI-провайд.│  │  Research     │  │  DOCX + ДСТУ  │
   │ OpenAI /   │  │  OpenAlex +   │  │  docx_writer  │
   │ Gemini     │  │  Tavily (агр.)│  │  dstu_formatter│
   └────────────┘  └──────────────┘  └──────────────┘
```

## Технології

| Рівень | Технологія |
|--------|-----------|
| AI / LLM | OpenAI (gpt-4o / gpt-4o-mini), Google Gemini (2.5-flash) |
| Оркестрація | `asyncio`, паралельний research і генерація |
| Дослідження джерел | OpenAlex API (наукові публікації), Tavily API (веб) |
| Надійність | `tenacity` (ретраї з backoff), `httpx` (async HTTP) |
| Домен-моделі | Pydantic v2 |
| Промпти | Jinja2-шаблони |
| Оформлення | python-docx, ДСТУ 8302:2015 |
| Веб | Flask + Flask-CORS, Server-Sent Events (SSE) |
| Конфігурація | YAML + python-dotenv |

## Початок роботи

### Передумови
- Python 3.10+
- Ключ OpenAI та/або Gemini
- (Опційно) ключ Tavily для веб-дослідження

### Встановлення

```bash
git clone https://github.com/solabuch/kursova_generator.git
cd kursova_generator

python -m venv venv
# Windows:
venv\Scripts\activate
# macOS/Linux:
source venv/bin/activate

pip install -r requirements.txt
```

### Налаштування

Створіть `.env` у корені:

```env
OPENAI_API_KEY=sk-...
GEMINI_API_KEY=...
TAVILY_API_KEY=...        # опційно, для веб-дослідження
```

Відкоригуйте `config.yaml` — виберіть пресет і налаштування проєкту:

```yaml
default_preset: standard   # economy | standard | quality

presets:
  standard:
    main:   {provider: gemini, model: gemini-2.5-flash}
    helper: {provider: openai, model: gpt-4o-mini}

project_settings:
  work_type: coursework    # coursework | report | essay | diploma
  input_toc_file: "input/toc.txt"
  output_dir: "output/"
```

## Використання

### 🌐 Веб-інтерфейс (рекомендовано)

```bash
python web/app.py
```

Відкрийте `http://127.0.0.1:5000`. Панель дозволяє редагувати зміст, обирати модель/пресет, слідкувати за логами генерації в реальному часі та регенерувати окремі розділи.

### 💻 CLI

```bash
python main.py --topic "Ваша тема" --toc input/toc.txt --output output/work.docx
# опційно передати методичку:
python main.py --topic "..." --methodology methodichka.md
```

### Результат

Готовий `.docx` у `output/`: структурована робота з розділами, посиланнями в тексті та списком використаних джерел, оформленим за ДСТУ.

## Як це працює

1. **Парсинг змісту** — будується ієрархічна структура з нумерацією розділів
2. **Blueprint** — планувальник класифікує розділи та визначає сутності/підтеми для дослідження
3. **Research (паралельно)** — для кожної теми збираються джерела з OpenAlex + Tavily, агрегуються й дедуплікуються
4. **Генерація (паралельно)** — автор пише кожен розділ на основі зібраних джерел і контексту; вступ і висновки — окремим проходом
5. **Збірка** — розділи об'єднуються, посилання перенумеровуються, бібліографія оформлюється за ДСТУ 8302:2015, результат експортується у DOCX
